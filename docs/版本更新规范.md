# 版本更新规范

**持久化指令 · v2.10.0 · 2026-10-13**

> 以下三条规范为每次版本发布或更新前的**强制回顾项**。
> 违反任一条将导致版本不一致、知识产权泄露或交付遗漏。

---

## 规范 1：版本号单一可信源，不得漂移

每次发布或更新版本时，版本号必须在以下**五处来源完全一致**：

```
┌─────────────────────────────────────────────────────────────┐
│                     版本号单一可信源                           │
│                   APP_VERSION = "2.10.0"                     │
│                  （webapp/app.py 运行时暴露）                   │
└──────────────────────┬──────────────────────────────────────┘
                       │
    ┌──────────────────┼──────────────────┐
    │                  │                  │
┌───▼────┐      ┌──────▼──────┐    ┌──────▼──────┐
│ pyproject │    │ CHANGELOG  │    │  Git tag   │
│ .toml    │    │ .md / -PUB │    │  v2.10.0   │
│ 2.10.0   │    │ ## v2.10.0 │    │            │
└────────┘      └────────────┘    └────────────┘
```

| 序号 | 来源 | 位置 | 校验方式 |
| --- | --- | --- | --- |
| 1 | 运行时版本 | `webapp/app.py` → `APP_VERSION` | `curl /api/health` |
| 2 | 构建版本 | `pyproject.toml` → `version` | `python -m tomllib` |
| 3 | 私有 CHANGELOG | `CHANGELOG.md` | `grep "^## v"` |
| 4 | 公共 CHANGELOG | `CHANGELOG-PUBLIC.md` | `grep "^## v"` |
| 5 | Git tag | `.git` → `tag` | `git tag --points-at HEAD` |

**执行时机**：每次 `git commit` 前校验，每次 `git push` 前校验。

**违规后果**：版本号漂移导致用户无法确定安装的是哪个版本，CI/CD 管道可能部署错误的产物。

---

## 规范 2：公共仓库 README 不得包含可逆向破解源码的敏感信息

公共仓库（GitHub Public / Gitee Public）的 README 文件**严禁**包含以下内容：

### 禁止内容清单

| 类别 | 具体禁止项 | 示例 |
| --- | --- | --- |
| API 接口定义 | 端点路径、HTTP 方法、请求/响应结构 | `POST /api/swarm/bid` |
| 源码级架构 | 模块划分、文件路径、函数签名、类定义 | `core/swarm.py: SwarmEngine.bid()` |
| 内部依赖 | 具体库版本、私有包名 | `fastapi>=0.110`, `core/rsi.py` |
| 实现算法 | 评分权重、词库结构、数据流路径 | "10 维评分权重：完播率 0.25" |
| 密钥/配置 | 环境变量名、端口、密钥路径、token | `BISU_GH_TOKEN`, `PORT=8000` |
| 构建细节 | 编译步骤、CI 配置、依赖安装命令 | `pip install -r requirements.txt` |
| 契约文件 | 绑定 JSON、追溯索引 | `core/contracts/ui_bindings.json` |

### 允许内容清单

| 类别 | 说明 |
| --- | --- |
| 产品介绍 | 用户可见的功能描述与能力列表 |
| 品牌资产 | 主色 token、SVG 图标、视觉规范 |
| 公开变更记录 | 用户级功能更新（不含技术细节） |
| 许可声明 | 专有软件许可 |
| 构建元数据 | 包名、版本号、依赖列表（不含安装命令） |
| 设计报告 | 非源码级设计文档 |

### 脱敏转换示例

| ❌ 私有版 | ✅ 公共版 |
| --- | --- |
| "23 个 API 端点，含 `POST /api/swarm/bid`" | "数字员工蜂群：合同网招标式任务调度" |
| "`core/swarm.py` 实现合同网算法" | "蜂群调度引擎：多角色并行执行" |
| "10 维评分权重：完播率 0.25，互动率 0.20..." | "10 维加权评分 + ABCD 等级" |
| "FastAPI 桥接层，懒加载引擎" | "API 服务层：统一接口、实时状态" |

**违规后果**：公开源码级信息导致核心知识产权泄露，可被逆向工程还原实现。

## 规范 3：私有库与公共库的 README 均须完成更新

每次版本发布时，**私有库与公共库的 README 必须同时更新**，不得遗漏任何一方。

### 更新范围

| 文件 | 所在仓库 | 更新内容 |
| --- | --- | --- |
| `README.md` | 私有库 | 完整技术文档：架构、API、配置、目录结构 |
| `README-PUBLIC.md` | 公共库 | 脱敏产品文档：功能、品牌、许可、联系 |
| `webapp/README.md` | 私有库 | 后端服务说明：API 端点表、启动方式 |

### 更新检查清单

发布前确认：

- [ ] `README.md` 已更新（私有库完整版，含架构与 API）
- [ ] `README-PUBLIC.md` 已更新（公共库脱敏版，仅产品介绍）
- [ ] `webapp/README.md` 已更新（后端服务说明，私有库内）
- [ ] 两份 README 的版本号一致
- [ ] 两份 README 的日期一致
- [ ] 公共版 README 已逐条对照「禁止内容清单」脱敏

**违规后果**：遗漏公共库 README 更新导致公共仓库信息过时，用户获取错误的产品信息。

## 附：版本发布前检查流程

```
┌──────────────────────────────────────────────┐
│              版本发布前检查流程                │
├──────────────────────────────────────────────┤
│                                              │
│  1. 更新版本号                                 │
│     webapp/app.py → APP_VERSION              │
│                                              │
│  2. 更新 CHANGELOG（私有 + 公共）              │
│     CHANGELOG.md + CHANGELOG-PUBLIC.md       │
│                                              │
│  3. 更新 README（私有 + 公共 + webapp）        │
│     README.md + README-PUBLIC.md             │
│     webapp/README.md                         │
│                                              │
│  4. 公共库脱敏审查                             │
│     逐条对照「禁止内容清单」检查                │
│     README-PUBLIC.md / CHANGELOG-PUBLIC.md   │
│                                              │
│  5. 构建安装包                                 │
│     python -m build --no-isolation           │
│                                              │
│  6. 版本一致校验                               │
│     bash scripts/verify_version_consistency  │
│     5/5 通过方可继续                           │
│                                              │
│  7. 合规检查                                   │
│     bash scripts/compliance_check.sh         │
│     公共库零源码确认                           │
│                                              │
│  8. Git 提交 + tag                            │
│     git add + git commit                     │
│     git tag -a v2.10.0                       │
│                                              │
│  9. 推送（私有库 → 公共库）                     │
│     git push origin main + v2.10.0           │
│     git push gh-public main                  │
│     git push gitee main                      │
│                                              │
│  10. 最终确认                                  │
│      三库版本号一致                            │
│      公共库零源码                              │
│      令牌零泄露                               │
│                                              │
└──────────────────────────────────────────────┘
```
