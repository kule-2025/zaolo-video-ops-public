# 双源部署方法论

**版本 v2.10.0** · 2026-10-13

---

## 1. 核心理念

ZAOLO 造流采用**双源分发**策略，将源码与文档分离到不同的公开级别，在保持品牌曝光与用户触达的同时保护核心知识产权。

```
┌─────────────────────────────────────────────────────────────┐
│                      版本号单一可信源                          │
│                    APP_VERSION = "2.10.0"                    │
│                   （webapp/app.py 运行时暴露）                 │
└──────────────────────┬──────────────────────────────────────┘
                       │
        ┌──────────────┴──────────────┐
        │                             │
┌───────▼────────┐           ┌────────▼─────────┐
│  私有仓库      │           │  公共仓库         │
│  GH Private    │           │  GH Public       │
│                │           │  Gitee Public    │
│ ─ 完整源码     │           │ ─ README（公开版）│
│ ─ 完整文档     │           │ ─ CHANGELOG（公开版）│
│ ─ CHANGELOG   │           │ ─ LICENSE          │
│ ─ LICENSE     │           │ ─ brand/（品牌资产）│
│ ─ 品牌资产     │           │ ─ docs/（设计文档）│
│ ─ .gitignore  │           │ ─ .gitignore      │
│ ─ dist/（产物）│           │ ─ pyproject.toml  │
│ ─ 所有配置文件 │           │   （元数据可见）   │
└────────────────┘           └──────────────────┘
```

## 2. 仓库矩阵

| 仓库 | 可见性 | 内容 | 用途 |
| --- | --- | --- | --- |
| `zaolo-video-ops-assistant` | GitHub Private | 完整源码 + 完整文档 + 品牌资产 + 构建产物 | 团队协作、CI/CD、私有分发 |
| `zaolo-video-ops-public` | GitHub Public | 文档 + 品牌资产 + 许可 | 品牌曝光、用户触达 |
| `zaolo-video-ops-public` | Gitee Public | 同 GitHub Public | 国内镜像、国内用户触达 |

## 3. 双源同步规则

### 3.1 版本号单一可信源

版本号在以下位置**必须完全一致**：

```
webapp/app.py          →  APP_VERSION = "2.10.0"   ← 运行时暴露
pyproject.toml         →  version = "2.10.0"        ← 构建元数据
CHANGELOG.md           →  ## v2.10.0                ← 私有库变更
CHANGELOG-PUBLIC.md    →  ## v2.10.0                ← 公共库变更
.git tag               →  v2.10.0                   ← Git 标签
```

**验证命令**：

```bash
# 1. 运行时版本
curl -s http://localhost:8000/api/health | python -c "import sys,json;print(json.load(sys.stdin)['data']['version'])"

# 2. 构建版本
python -c "import tomllib;print(tomllib.load(open('pyproject.toml','rb'))['project']['version'])"

# 3. 私有 CHANGELOG
head -20 CHANGELOG.md | grep -m1 "^## v"

# 4. 公共 CHANGELOG
head -20 CHANGELOG-PUBLIC.md | grep -m1 "^## v"

# 5. Git tag
git tag --points-at HEAD | grep "^v"
```

### 3.2 内容同步流程

每次版本发布时，按以下顺序执行：

```
1. 更新版本号        → webapp/app.py (APP_VERSION)
2. 更新 CHANGELOG   → CHANGELOG.md（私有）+ CHANGELOG-PUBLIC.md（公共）
3. 更新 README      → README.md（私有完整版）+ README-PUBLIC.md（公共脱敏版）
4. 构建安装包       → python -m build --no-isolation
5. 本地提交 + tag   → git add + git commit + git tag -a v2.10.0
6. 推送私有库       → git push origin main + git push origin v2.10.0
7. 推送公共库       → git push gh-public main + git push gitee main
8. 版本一致校验     → 运行校验脚本（见 §5）
```

### 3.3 公共库脱敏规则

公共仓库**严禁**包含以下内容：

| 禁止项 | 说明 | 对应文件 |
| --- | --- | --- |
| 可运行源码 | 任何 `.py`、`.js`、`.html` 引擎代码 | `core/`、`webapp/`、`prototype/` |
| API 接口定义 | 端点路径、请求/响应结构 | `webapp/README.md` |
| 内部架构细节 | 模块划分、引擎依赖、数据流路径 | `docs/系统设计文档.md` |
| 内部配置 | 环境变量名、端口、密钥路径 | `.env`、`requirements.txt` |
| 源码级文档 | 函数签名、类定义、算法伪代码 | `docs/前后端拉通-实现方案-v2.md` |

公共仓库**可以**包含：

| 允许项 | 说明 | 对应文件 |
| --- | --- | --- |
| 产品介绍 | 用户可见的功能描述 | `README-PUBLIC.md` |
| 品牌资产 | 主色 token、SVG 图标、视觉规范 | `brand/` |
| 公开变更记录 | 用户级功能更新 | `CHANGELOG-PUBLIC.md` |
| 许可声明 | 专有软件许可 | `LICENSE` |
| 构建元数据 | 包名、版本号、依赖列表 | `pyproject.toml` |
| 设计报告 | 非源码级设计文档 | `docs/`（经筛选） |

## 4. 令牌安全管理

### 4.1 令牌存储

| 环境变量 | 平台 | 用途 |
| --- | --- | --- |
| `BISU_GH_TOKEN` | GitHub | 私有库与公共库的 API 认证 |
| `BISU_GITEE_TOKEN` | Gitee | 公共库的 API 认证 |

### 4.2 令牌使用规范

- **仅用于授权认证**：令牌仅通过 `Authorization: Bearer <token>` 或 `?access_token=<token>` 传递给 API
- **通过环境变量引用**：严禁硬编码在代码、脚本、配置文件中
- **严禁明文写入**：不得写入 `.env`、日志、README、CHANGELOG、git 提交信息
- **严禁外泄**：不得通过消息、截图、文档等形式传播
- **最小权限原则**：仅授予完成当前任务所需的最小权限集

### 4.3 令牌泄露应急

若令牌疑似泄露：

1. **立即吊销**：在平台管理后台 revoke 该令牌
2. **生成新令牌**：创建新令牌并更新环境变量
3. **审计日志**：检查泄露窗口期内的 API 调用记录
4. **通知团队**：知会相关安全负责人
5. **更新 CHANGELOG**：记录安全事件（仅公共描述，不含令牌细节）

## 5. 版本一致校验脚本

```bash
#!/usr/bin/env bash
# verify_version_consistency.sh — 校验版本号在四处来源的一致性
set -e
PROJECT_DIR="$(cd "$(dirname "$0")/.." && pwd)"
cd "$PROJECT_DIR"

VERSIONS=()

# 1. 运行时版本
RUNTIME=$(curl -s http://localhost:8000/api/health 2>/dev/null | python -c "import sys,json;print(json.load(sys.stdin)['data']['version'])" 2>/dev/null || echo "SERVER_OFFLINE")
VERSIONS+=("runtime:$RUNTIME")

# 2. 构建版本
BUILD=$(python -c "import tomllib;print(tomllib.load(open('pyproject.toml','rb'))['project']['version'])")
VERSIONS+=("pyproject:$BUILD")

# 3. 私有 CHANGELOG
PRIV=$(head -30 CHANGELOG.md | grep -m1 "^## v" | grep -oE "v[0-9]+\.[0-9]+\.[0-9]+")
VERSIONS+=("changelog-priv:$PRIV")

# 4. 公共 CHANGELOG
PUB=$(head -30 CHANGELOG-PUBLIC.md | grep -m1 "^## v" | grep -oE "v[0-9]+\.[0-9]+\.[0-9]+")
VERSIONS+=("changelog-pub:$PUB")

# 5. Git tag
TAG=$(git tag --points-at HEAD 2>/dev/null | grep -m1 "^v" || echo "NO_TAG")
VERSIONS+=("git-tag:$TAG")

echo "=== 版本一致校验 ==="
for v in "${VERSIONS[@]}"; do
  echo "  $v"
done

# 校验
EXPECT="${VERSIONS[1]}"  # 以 pyproject 为准
PASS=0
for v in "${VERSIONS[@]}"; do
  KEY="${v%%:*}"
  VAL="${v#*:}"
  if [ "$VAL" = "SERVER_OFFLINE" ] || [ "$VAL" = "NO_TAG" ]; then
    echo "  ⚠️  $KEY: $VAL (跳过)"
  elif [ "$VAL" = "$EXPECT" ]; then
    echo "  ✅ $KEY"
    PASS=$((PASS+1))
  else
    echo "  ❌ $KEY: $VAL (期望 $EXPECT)"
  fi
done
echo "=== 通过: $PASS / 5 ==="
```

## 6. 合规检查清单

每次发布前确认：

- [ ] 版本号在 5 处来源完全一致
- [ ] 公共仓库不含任何 `.py` 源码
- [ ] 公共仓库不含 API 端点定义
- [ ] 公共仓库不含内部架构细节
- [ ] 公共仓库不含 `.env` 或密钥引用
- [ ] 公共仓库 CHANGELOG 已脱敏（仅用户级描述）
- [ ] 公共仓库 README 已脱敏（仅产品介绍）
- [ ] 私有仓库含完整 CHANGELOG（含技术细节）
- [ ] 私有仓库含完整 README（含架构与 API）
- [ ] 构建产物（wheel/sdist）已验证内容完整
- [ ] Git tag 已创建并推送
- [ ] 令牌未泄露在任何文件中
