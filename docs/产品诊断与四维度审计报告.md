## 二、业务闭环完整性审计（四维度之二）

### 2.1 S1→S8 主链路

```
S1 需求解析 → S2 策略分析 → S3 选题 → S4 脚本 → S5 合成 → S6 剪辑 → S7 审核 → S8 评论
   ↓              ↓             ↓         ↓          ↓         ↓        ↓         ↓
结构化需求   形式+窗口+垂类  选题卡    爆款脚本    视频草稿   成片     人工审核    回复计划
                (策略)      (钩子+热度)  (5段式)  (mock)    (元数据)  闸门       (模板)
```

**本轮修复的闭环断裂点**：
- ❌ 修复前：回退重跑 `REPLAY_SKIPPABLE` 缺失 → S7 驳回后沿用旧成片发布
- ✅ 修复后：仅跳 S1-S3，S5-S8 强制重跑（单测 `test_rollback_replays_downstream_only` 验证）

**仍存在但未闭合的断裂**：
- ❌ **S5 合成未真正生成视频**：`render_status="mock"`，无实际 MP4 产出。这是**最关键**的闭环断裂——"合成"和"剪辑"两步在系统里都是契约占位。
- ❌ **S6 剪辑是元数据操作**：只写 `metadata={duration, cover, tags}`，无实际剪辑动作。
- ❌ **S8 回复未回流**：模板生成的回复**不会真的发布到评论区**（无微信 API 集成）。
- ❌ **RSI 观测源是模拟历史**，非真实完播率/互动数据。

## 五、业务链路与数据流诊断

### 5.1 完整业务链路（用户请求的 9 环节）

| 环节 | 系统当前覆盖 | 数据流是否打通 | 瓶颈 |
|---|---|---|---|
| 热点筛选 | S2 策略分析（形式+窗口+垂类） | ✅ 内部闭环 | **无外部热点源**（缺抖音热榜、微信热榜 API） |
| 选题 | S3 选题卡（title + hooks + heat_score） | ✅ 内部闭环 | 无 LLM 生成，纯规则 |
| 素材采集 | ❌ 缺失 | ❌ | 无素材库 |
| 脚本生成 | S4 爆款脚本（5 段式） | ✅ 内部闭环 + 自动重写回路 | 规则层模板 |
| 配音 | ❌ 缺失 | ❌ | 无 TTS |
| 视频生成 | ❌ S5 mock | ❌ | 无生成模型 |
| 剪辑 | ❌ S6 mock | ❌ | 无 ffmpeg |
| 成片 | S6 metadata 元数据 | ⚠️ 部分（元数据级） | 无实际成片 |
| 平台发布 | S7 审核 → 发布计划 | ⚠️ 部分（计划级） | 无 API |

**核心诊断**：**9 个环节中，4 个环节（素材/配音/生成/剪辑）完全缺席，2 个环节（成片/发布）停留在元数据/计划层**。系统是"生产线骨架"，非"生产线实体"。

### 5.2 数据孤岛识别

| 孤岛 | 现象 | 影响 |
|---|---|---|
| 历史内容 | `HISTORY_BY_VERTICAL` 按垂类硬编码，非动态拉取 | RSI 观测失真 |
| 评论样本 | `COMMENTS_BY_VERTICAL` 静态 4 条，非实时 | S8 分类训练数据不足 |
| 播放量 | 模拟"预估播放"，无真实回流 | 无法做真正 A/B 学习 |
| AI 引用率 | 模拟数值 | GEO 引擎无外部信号校验 |
| 引流 ROI | 模拟漏斗数据 | 无法做真正 ROI 归因 |

### 5.3 关键指标健康度（基于代码实现）

| 指标 | 当前值 | 行业基准 | 差距 |
|---|---|---|---|
| S4 分档合格率（A/B 级占比） | 演示中 76/A、67/B（v1） | 爆款完播率 >30% | 目标 A 级占比 ≥30% |

## 六、可落地修复方案（含量化指标）

### 6.1 P0 修复方案（2-4 周，最小可交付闭环）

#### 方案 A：接入真实视频生成（针对 P0-1）

**技术路径**：
1. 抽象 `VideoGenerator` 接口（`generate(script, style, aspect_ratio) -> VideoAsset`）
2. 首批接入 2 家：
   - **可灵（Kling）**：中国合规、10s/720p，¥0.5/条，中文友好
   - **Runway Gen-3/4**：全球标杆、10s/1080p，$0.10-0.30/条
3. 备选：豆包、腾讯混元、Sora 2、PixVerse、Pika、Vidu

**量化预期**：
- 单条视频生成成本：从"未产出"到 **¥3-5**（比传统 2800 元降 **99.8%**）
- 单条生成耗时：**10-30 分钟**（行业标杆，比传统 3-5 天降 90%+）

#### 方案 B：接入 ffmpeg 剪辑时序（针对 P0-2）

**技术路径**：
1. 抽象 `VideoEditor` 接口（`edit(assets, timeline) -> FinalVideo`）
2. 支持：转场（0.5s 淡入淡出）、字幕（ASS 格式）、BGM（音量混合）、时长校准（≤60s）
3. 输出 MP4 H.264 编码，1080×1920 竖屏

**量化预期**：
- 剪辑耗时：**2-5 分钟**（对比 CapCut 手工 30-60 分钟）

#### 方案 C：接入 TTS（针对 P0-6）

**技术路径**：
1. 抽象 `TextToSpeech` 接口
2. 首选：火山引擎 TTS（多音色、情感调节）、腾讯 TTS、MiniMax 海螺语音、豆包语音

**量化预期**：
- 100 字脚本配音耗时 **30 秒**，成本 **¥0.05/千字符**

#### 方案 D：接入 LLM 生成脚本（针对 P0-5）

**技术路径**：
1. S3 选题 & S4 脚本引入 LLM
2. 首选：DeepSeek V3（性价比）、豆包（中文强）、GPT-4o（推理强）
3. 保留规则层评分作为**质量守门**（LLM 生成 → 规则评分 → 不达标重写）

**量化预期**：
- 脚本合格率（规则评分 ≥75）从当前 **~60%** 提升到 **85%+**
- 内容多样性：从 5 段式模板 1 种 → LLM 可生成 10+ 种结构

#### 方案 E：接入视频号 API（针对 P0-3、P1-5）

**技术路径**：
1. 微信开放平台内容 API（需企业资质）
2. 支持：发布、拉取评论、回复、拉取作品数据

**量化预期**：
- 单条视频发布耗时从"人工"→ **秒级**
- 评论回复自动化率 **≥80%**（其余需人工审核）

### 6.2 P1 修复方案（3-6 周）

#### P1-1：双引擎评分对齐
- **技术路径**：写一个双引擎对拍测试（Python + JS 同输入），逐维子项比对差值
- **量化预期**：JS/Python 评分差从当前 20 分降至 **≤3 分**

#### P1-4：GEO 对接真实 AI 入口
- **技术路径**：接入元宝搜索 API、豆包搜索 API，拉真实 AI 引用率数据
- **量化预期**：GEO 指标从"模拟"变真实，AI 引用率可提升 **3-5 倍**（行业均值 4.2% → 目标 15-20%）

### 6.3 P2 修复方案（3-6 月）

- **A/B 测试框架**：多版本自动分桶 + 长期追踪，参考 YouTube A/B testing 实践

## 十、报告局限性与诚实声明

1. **未接入真实数据**：本报告中的爆款率、完播率目标基于**行业公开报告**，不代表本系统实测数据——本系统目前无真实视频产出。
2. **竞品数据来自第三方**：CapCut/剪映的收入、DAU、GMV 等数据来自 `aitoolscoop.com`、`breakevenpointcalculator`、`三个皮匠报告`、`友望数据` 等第三方统计，可能与官方口径存在差异。
3. **算法机制数据来自算法白皮书 + MCN 实测**：视频号"完播率 42% 权重"、"社交推荐 55%"等指标来自 2025 算法白皮书与 MCN 实测分享，官方未逐字确认。
4. **本系统无历史真实用户数据**：所有 RSI 循环观测输入是**静态历史样本**（`HISTORY_BY_VERTICAL`），非真实平台回流。
5. **原型是交互演示而非产品**：`prototype/index.html` 是 2136 行单文件演示，不含后端 API，不能作为生产系统直接部署。
